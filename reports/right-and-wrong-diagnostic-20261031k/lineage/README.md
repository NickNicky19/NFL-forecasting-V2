# What the focal forecasts actually used

The passing-yard HGB and completion D1 forecasts are direct target procedures. Neither forecast was generated as predicted attempts multiplied by a saved conversion or gain forecast. Their misses therefore cannot be divided into opportunity/conversion component errors. Actual attempts, completions and yards can describe the games afterward; those statistics are separate from model components and pregame information.

This is a read-only lineage inspection, not a new accuracy experiment. The retained I comparison remains the numerical evidence: HGB L1/H-MULTI passing yards had MAE60.082677 and28/80 correct selected directions; D1/H-MULTI completion lower median had MAE5.052632 and33/76. The numeric worker owns K's new correct/incorrect buckets and all new loss calculations. No source prediction, selection, outcome or scoring version was changed here.

The actual fitting calls receive the matrices recorded in the query packets, and the retained fitted objects confirm their20/48 model dimensions and split-feature indices. This is stronger than identifying a field name in a file. It does not establish the effect of changing a feature, the path contribution for a specific player or a causal explanation of an error. No tree was traversed for a new query and no `predict`, `apply` or `fit` method was invoked during inspection.

The HGB objective is direct absolute error, with64 iterations, depth3, learning rate.05 and the retained fixed configuration. It does not provide an authenticated numeric forecast distribution. D1 uses32 squared-error ExtraTrees partitions, depth8/minimum leaf30, equal-tree empirical response laws and the5% same-arm role/global prior, then extracts a lower median. A forest lower median is not a direct absolute-loss fit. Mean and median views share the same learner.

Both fit relationships are pooled across eligible earlier QB rows. Player IDs join the right history but are not model input encodings. D1 response leaves compare feature states of training observations; they are not an explicit learned-neighbor or causal matchup method. HGB has no opponent field in this recipe. D1 adds four opponent-position qualified production/coverage fields, not personnel, pressure, coverage, current weather or upcoming game script.

The own summaries use the player's target values: yards for passing yards, completions for completions. `n3`/`n8` count finite target observations in the last3/8 stat slots; they are not plays, snaps or attempts. The ordered block retains four target values, known scheduled-kickoff ages and missingness. Missing target slots remain represented. D1 averages the last four **observed** qualified opponent/position group totals, retaining observed incomplete groups; an absent group creates no slot. These are partial qualified-population totals, not complete official team totals. The D2 audit may contain league/rate fields, but those fields are absent from D1's24-column vector. Reading a shared audit field is not proof it entered D1.

These ages must stay separate:

- **Game age in a model feature:** the stored lag age at the known scheduled target kickoff. This value is retained unchanged when an earlier-decision reconstruction proves all underlying inputs eligible. It is not recomputed as an earlier-decision age.
- **Assumed availability age at decision:** decision time minus the latest consumed source-availability timestamp under the seven-day assumption. It can be much shorter than game age. In the admitted W6 passing-yard panel its maximum is279.7456days; the oldest stored lag1 game age is286.8160days. This establishes a stale own-history case, not its causal effect or an undocumented role change.
- **Training-input age:** decision minus the latest eligible training label or consumed training feature. These are distinct from the nominal weekly fit origin and actual reconstruction execution clock.
- **Quote age:** unknown. An archive retention clock is not an authenticated bookmaker update clock.

For four admitted focal rows per procedure, the nominal weekly fit-origin timestamp follows the retained threshold decision. All consumed dependencies qualify; these are reconstructed as-of procedures, not a claim that the original later execution occurred before the decision. ## Components and recoverability

[The component census](FROZEN_COMPONENT_FORECAST_CENSUS.json) covers the current finite V2 library, the18 I recipe/output choices per target and the public4,832-view legacy inventory. It finds **zero compatible frozen physical-component forecast packages in this inspected executable set**. This is a bounded statement, not a claim that no owner ever tested a workload model. The located74 related legacy views include32 `ridge_without_workload` negative-control views;42 reported potential workload/held-volume views remain at their actual `REPORTED_NOT_REPRODUCED` level. A method label or a reported aggregate does not establish retained per-game component forecasts.

Empirical, HGB, Leaf/C02/D1/D2 and direct GLM laws are marginal forecasts. A selector routes an existing marginal point. Their rates, priors, missing indicators and distribution parameters are not automatically separately forecast physical exposures. Saved raw/adjusted references retain unknown internal model/component metadata. Their actual saved points can still be compared without inventing those internals.

The separate [postgame context contract](POSTGAME_CONTEXT_ADMISSION.json) pins nine existing HGB query packets for passing attempts/completions/yards. The private in-memory helper reconstructs96 qualified player-game contexts with288 explicit target values and15 ratio nulls due to nonpositive denominators. It keeps signed yards, missingness and exact identities. No player rows are published or newly persisted, and no errors, buckets or scores are calculated by this helper. A true component-error analysis still needs the original same-procedure forecast opportunities/conversions/gains or coherent joint law, its clock and earlier-out-of-fold training provenance.
