# B aligned timing sensitivity: source-policy feasibility

The retained PBP snapshots have asset-update, HTTP Last-Modified and November7 retrieval clocks. They do not retain authenticated per-game historical observation/publication versions. A change to actual historical availability cannot be established from these bytes. The registered alternative is therefore an explicitly reconstructed timing sensitivity. It makes no assertion that a one-day feed existed, or that current revised statistics and corrections were actually known after48hours.

The sole alternative is kickoff plus48hours, admitted strictly before each cutoff. Two days provide a deliberately conservative game-duration/processing allowance for ordinary completed games; the size is a predeclared operational hypothesis, not measured publication latency or proof of finality. Postponed/unfinished games and true observed/versioned sources need their own qualified contracts. The comparison keeps the seven-day policy, same revised source values, player/role population, learner, tuning, output and selection policy as its control.

Alignment includes historical training/query features, label admission, earlier-label prior membership, own/team history, existing defense residual/support and the earlier offense-quality baselines used to construct those residuals. Existing own-mix×defense-residual products follow the selected clock on both sides. There is no frozen seven-day defense branch, no new R3 defensive-value architecture and no current-role addition. Any observed defensive-information effect is part of timing, not a newly tested defense model.

This differs from the completed availability A/B/C experiment. That earlier study tested current-snapshot query transfer and a limited label refresh while retaining seven-day historical training-feature clocks. It is reused as relevant evidence but does not complete this aligned comparison.

The wrapper lives in `nfl_v2/qb_aligned_freshness.py`; frozen context, opportunity, incremental-model and adapter modules are unchanged. It accepts only declared seven-day input reconstruction records. Explicit null/nonfinite availability remains unresolved. A wholly absent availability column can be reconstructed only under explicit separate permission; a partly missing column cannot inherit it. Observed/versioned clock routes are outside this sensitivity and are never overwritten.

Canonical uniqueness is player/game for QB records and team/game for team records. Conflicting team/opponent metadata cannot create extra observations. History is admitted by eligible availability first and then selected by game time, with strict `<` preserved. The original opportunity class still rejects non-seven-day inputs. The new policy-specific class validates exact declared policy identity/delay without weakening the old guard. Variable observed-clock use remains unqualified: the older HGB helper has a known ordering limitation on such inputs; fixed-delay policies preserve game-time/availability order and do not invoke that unsupported route.

`AlignedFreshnessBundle` exposes policy-bound rows, context history, opportunity history, direct features, training membership, feature order and actual admitted-source summaries. A future query needs canonical identity/cutoff, not its own final outcome or outcome-availability clock. No target-game actual exposure is read.

Eight deterministic fixtures cover unchanged seven-day feature parity; aligned training/query/defense history; future/target mutation; explicit unknowns; absent-column distinction; admission-before-game-time recency (last-three mean20, not50); conflicting identity/version rejection; old guard preservation; and outcome-free queries. They add no NFL evaluation games or weeks.

The bound derivative preserves the original source bindings and marks every converted row as reconstructed sensitivity. `SOURCE_AND_CLOCK_FEASIBILITY_V1.json` reports actual support changes without reporting predictive gain. Root owns the separately frozen fit/scoring package. Missing authentic clocks do not justify claiming actual old publication times; completion of this source component is not evidence of accuracy, capture, delivery or release.
