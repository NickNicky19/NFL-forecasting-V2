## Timing-test acceptance criteria and API recommendation

The prior `B_FRESHNESS_RECIPE_SCOPE_V1.json` explicitly describes the old A/B/C availability wave as query-transfer and limited Week 7 refit sensitivity. Historical training features remained under the seven-day rule. No complete aligned historical training-and-query test was found in that existing scope. The new treatment therefore closes a named missing test rather than repeating it.

Use four bound arms without changing learner capacity, objective, seed, history windows, prior strengths or tuning:

| Arm | Recipe | Information policy |
|---|---|---|
| F0 | Existing E3/R0 | Existing strict kickoff + seven days |
| F1 | Existing R2 | Existing strict kickoff + seven days |
| F2 | E3 | Declared kickoff + 48-hour sensitivity |
| F3 | R2 | Same declared 48-hour sensitivity |

F2−F0 and F3−F1 measure the full aligned timing-policy changes. F1−F0 and F3−F2 compare the profile increment within each timing policy. Do not add the former R3 raw-defense block only to an alternative arm. Existing E3 opponent residuals stay in all arms and must be reconstructed under each arm's own earlier-only clock; their changed eligible history is part of the timing treatment, not evidence of a new defense architecture.

The new wrapper preserves the old seven-day module and guard. It converts only explicitly declared reconstructed source rows, refuses explicit unknown clocks, and separates unavailable observed-clock routes. A wholly absent clock column requires its own declared policy. Upcoming queries do not need final outcomes. Admission precedes recent-game selection; windows and identity/version handling stay deterministic.

Fixed-delay alternatives preserve the equivalence between game-time and availability ordering. The old helper's latent nonmonotone-publication ordering limitation is therefore not demonstrated contamination here. An actual variable observed-clock extension still requires its own qualification and admission-then-game-time recency handling. The wrapper's independent helper fixture is software capability evidence, not an implemented authenticated source route.

Retain the 48-hour assumption in protocol, source rows, feature/query records, model/prior bindings and outputs. It is not verified original publication, proof of finality at 48 hours, genuine fresh capture, or automatic eligibility for a primary website change. Previously inspected seasons remain exposed development evidence. The existing five-week and owner-controlled delivery rules remain separate.
